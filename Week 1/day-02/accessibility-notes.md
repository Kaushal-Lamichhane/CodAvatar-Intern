
# Day 02 — Accessibility Notes

## Semantic structure
The page uses header, nav, main, section, article, and
footer elements to give content meaningful structure.

## Headings
The page uses a logical heading hierarchy so users can
understand its sections.

## Labels
Every form input has a label associated through matching
for and id attributes.

## Native controls
The page uses real buttons, links, inputs, a select,
a textarea, and a checkbox rather than clickable divs.

## Form validation
Required fields and native validation attributes help
the browser identify missing or invalid input.

## Keyboard accessibility
I tested navigation using Tab, Shift + Tab, Enter,
Space, and arrow keys where appropriate.

## Limitations
The task cards are static. Form submission demonstrates
native HTML behavior only. No tasks or accounts are saved.

## Improvements for later
- Add CSS for responsive layout and visible focus states.
- Add JavaScript task creation and completion.
- Add clear success and error feedback.
